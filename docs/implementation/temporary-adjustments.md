# 临时调课工作台

临时调课按已确定的安排直接录入，再检查冲突、核对并发布。入口为“日常运行 → 临时调课”，班级、老师、教室和补课任课关系复用现有选择器。

调课由有权限的教务人员直接操作，系统检查冲突，操作者核对前后安排并确认发布后立即生效。产品不设申请、人工审核或审批流程。老师查看实际课表和变更消息，消息是否已读不影响调整生效。

## 操作方式

入口“日常运行 → 临时调课”默认显示调整事项和一份未发布草稿，不加载整周课表。每条事项直接显示课程、老师、原安排、新安排、发布 / 撤回状态及老师消息查看情况。

1. 点击“新建调课”，直接输入老师、班级或教室名称查找，支持拼音、首字母和教师工号。“按分类选”保留原有选择器。默认列表只显示相关课程，可快速切换今天、明天、整周。课程搜索、筛选与“对照课表”集中在列表上方；空课节可安排补课。
2. 选中原课后进入“设置新安排”。常用操作与长期调课同序：“换课、改时间、换老师、换教室”；“更多调整”保留停课和活动。补课可以从事项页更多菜单或选课页底部进入。
3. 换课直接指定目标日期、课节和班级，再点击那一节课程。班级默认原课程所属班，复用现有班级选择器；浏览多个结果时可按老师或课程搜索。需要浏览整天时选择“查看当天全部课节”。课程按时间显示，冲突原因直接标在对应行，不推荐三个方案、不隐藏冲突课程。切换日期、课节或班级会清空此前选择，避免提交旧目标。
4. 改时间直接填写新日期和课节；换老师、换教室直接使用现有选择器。原课程放在左侧摘要栏，右侧集中设置目标安排；选好后显示简短的交换说明。下一步统一检查实际课表冲突，包括教师请假。
5. 目标安排标题旁的弱入口“查看周课表”按需展开原课和交换课程所在的班级及周次，只显示调整前的实际安排，不修改表单。
6. 直接填写原因（不提供常用原因菜单）后点击“下一步：核对”，核对每节课的调整前后日期、课节、教师、教室和接收老师，再“确认发布”。双节交换一次提交，两侧一起生效。有冲突时禁止发布，明确提示返回修改。
7. 返回事项页可按老师、班级、课程或原因搜索，也可按日期、类型、发布 / 撤回状态筛选。搜索包含交换两端和代课老师，在服务端分页前执行。日期范围命中交换任意一侧均能找到记录。
8. 打开记录详情查看原因及消息回执，按需撤回整组。撤回恢复原安排，遇到后续代课或资源冲突会阻止执行。

原课筛选的课程多选为“或”，课程、时段、状态、文字搜索之间为“且”。条件标签可单独删除，“清空条件”保留日期和对象；切换老师 / 班级 / 教室时清除上一对象的筛选。原课查找条件保存在地址栏。

临时和长期调课共用页头、记录搜索与筛选、选课工具栏、课程摘要、调整方式、目标课程列表、前后对照和底部操作栏。两页统一为“选择课程 → 设置新安排 → 核对发布”，顶部使用紧凑的横向步骤导航，区分已完成、当前和后续步骤，不重复显示大标题或步骤卡片。选课搜索和列表归入一个工作面板；编辑页左侧为原课摘要，右侧为操作标签、目标安排和原因，完整前后对照集中在核对页。当前操作使用实色文字标签标识。窄屏将原课压缩为两列摘要，底部保留主要操作。底部提示缺少的目标或原因。业务差别通过单次日期或按周生效区间表达。

未发布方案可以暂存，离开页面或刷新时也会暂存有修改的方案。每个用户、学期在本浏览器保存一份草稿，继续处理仍需重新预览。放弃或发布另一份方案不会清除已有的不同草稿。草稿不会改变实际课表。

## 数据与消息

- 基础周课表保持原样，临时调整只作用于指定日期的实际课程。跨日期交换分别读取两端当日生效的版本；长期调课覆盖其中一端时分别重绑定。
- 候选、预览、发布共用实际课表冲突检查，包括班级、全部任课教师、教室与请假。发布时重新检查并校验版本标记；并发更新会保留表单，让用户重新预览。
- 目标课程接口在分页前按日期、范围、目标班级 `target_class_id`、关键词和 `target_item_id` 筛选，按日期与上课时间排序。返回分页内所有匹配结果及不可选原因，不做推荐或优先级排序。指定目标班级时优先使用该班级筛选，合班课程按全部成员班级匹配。
- 临时调整与站内消息在同一个数据库事务中写入。消息写入失败会回滚本次调整；可以在预览页取消生成消息。
- 老师端铃铛展示本人当前学期的消息。打开具体消息详情后才记为已查看，提供前后对照与“查看当天实际课表”。列表加载不等于老师已查看。
- 撤回生成独立的撤回消息，并使用当前恢复安排的资源信息；原发布消息仍保留历史快照。未选择生成消息的调整，撤回也不额外生成消息。
- 消息是站内消息，没有接入短信、微信或外部推送。

停课会空出原时段。活动仅标记活动名称并停上原课程，页面显示的原教师和教室不表示已安排看班或预约活动资源；选择页与确认页都会说明。

## 交付范围

合班与协同教师作为单条课程的完整成员一起显示、检查和调整。教师请假仍从现有“请假与代课”入口查看影响并批量安排代课。本次重做管理端直接调课和查看调整记录的流程，老师端沿用实际课表和站内消息。

设计稿中的跨多条记录的连排、同步课程自动联动，以及教室停用后的批量处理队列尚未加入本轮工作台。草稿没有跨设备同步；目前没有教师负担排名和外部通知送达回执。
