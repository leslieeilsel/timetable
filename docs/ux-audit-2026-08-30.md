## 结论

当前代码的工程验收结果已达到“可用且顺手”的目标：20 个规范路由均完成桌面与移动 Lighthouse；所有最终报告的 Accessibility、Best Practices、SEO 均为 100；桌面 Performance 全部 100，移动最低 95；核心角色、登录、退出、强制改密、排课流程、资料维护入口、课表视图、临时调课、请假与系统设置均经过实际交互。最新的可访问名称修复已经通过 check/test/build，但发生在现有 Lighthouse 报告之后，因此仍保留一项 High 级“验证待完成”，不把代码通过等同于浏览器验证通过。

正式 UX verdict 仍为 `Incomplete`：严格审计协议要求每页都保留完整交互时间线并最终逐页复跑 axe-core；Chrome 在收尾复跑前已不再运行，且本次没有获得执行删除、发布等不可逆操作的授权。Lighthouse Accessibility 100 是有力佐证，但不能替代 axe-core 硬门槛；`label-content-name-mismatch` 在 Lighthouse 分类中权重为 0，即使该规则失败也可能仍显示 Accessibility 100。

## 发现与修复状态

### F-H1 `[✓ fixed]` 跨账号后退恢复旧身份

- Layer：Architecture / Feedback
- Severity：High
- Surface：登录、退出、工作台；桌面 Chrome
- Persona：排课员在共用教务电脑上切换账号
- Reproduce：1. viewer 登录；2. 退出；3. scheduler 登录；4. 浏览器后退。
- Observed：历史页面可能从 bfcache 恢复 viewer 姓名/权限，当前会话实际已是 scheduler。
- Expected：任何历史恢复都必须重新确认当前服务端会话，不能短暂展示旧账号。
- Evidence：实测复现后，修复回归得到 `{path: "/", schedulerIdentity: 1, viewerIdentity: 0}`；最终控制台 0 error/0 warning。
- Suspected location：`apps/web/src/lib/auth.tsx:50`
- Smallest possible patch：监听 `pageshow` 的 persisted 恢复，先隐藏旧根节点再重载并重新获取 `/me`。

### F-H2 `[✓ fixed]` 768–1024px 固定侧栏挤压主内容

- Layer：Architecture / Visual
- Severity：High
- Surface：教师、用户、学年、任课矩阵、方案生成、临时调课、请假；768px/1024px
- Persona：使用小屏笔记本或横屏平板的排课员
- Reproduce：1. 打开任一长表格页面；2. 视口设为 1024px 或 768px；3. 检查主内容宽度和横向溢出。
- Observed：固定侧栏过早启用，主内容被压到不可用宽度，多页出现文案/表格溢出。
- Expected：1280px 以下使用抽屉导航，主工作区占满可用宽度。
- Evidence：初始 114 次矩阵定位问题；修复后 38 次针对性复查为 0 overflow/0 collapse；`mobile-sidebar-open.png` 证明抽屉可用。
- Suspected location：`apps/web/src/hooks/use-mobile.ts:3`、`apps/web/src/components/ui/sidebar.tsx:209`、`apps/web/src/components/workspace-shell.tsx:86`
- Smallest possible patch：统一把桌面侧栏断点提升到 1280px（Tailwind `xl`），触发器在同一断点切换。

### F-H3 `[✓ fixed]` 临时调课页面首屏大幅跳动

### F-H4 `[✓ fixed]` 方案生成首屏加载非必要大数据

- Layer：Architecture / Feedback
- Severity：High

- Persona：进入页面后优先使用推荐自动排课的排课员

### F-M1 `[✓ fixed]` 强制改密流程没有退出路径

- Layer：Interaction / Feedback
- Severity：Medium
- Surface：`/change-password`
- Persona：在共用电脑误登录或暂时不能设置新密码的用户
- Reproduce：1. 使用 `must_change_password` 账号登录；2. 到强制改密页；3. 尝试离开当前账号。
- Observed：页面只能继续改密，没有可发现的退出登录动作。

### F-C1 `[✓ resolved]` 表单可访问语义不完整

- Layer：Interaction
- Severity：Critical（初始 `button-name` / `aria-allowed-attr` 规则）
- Surface：修改密码、系统设置、日期选择器
- Persona：键盘/屏幕阅读器用户，以及高压下快速纠错的排课员
- Reproduce：1. 提交密码不一致；2. 使用辅助技术读取错误；3. 检查设置下拉框和必填日期触发器名称。
- Observed：错误只靠视觉位置；选择器名称不够稳定；按钮错误使用 `aria-required`。
- Expected：错误通过 `aria-invalid`/`aria-describedby` 与字段关联；选择器有持久标签；必填信息进入可访问名称而非无效属性。
- Evidence：初始 desktop/mobile settings 的 `button-name` 各有 2 个失败节点，adjustments 的 `aria-allowed-attr` 各有 1 个失败节点；生产复跑中这些规则均为 1/通过。前端 check/test/build 同时通过。
- Suspected location：`apps/web/src/components/page.tsx:61`、`apps/web/src/pages/change-password-page.tsx:111`、`apps/web/src/pages/system-pages.tsx:494`、`apps/web/src/components/date-picker.tsx:89`
- Smallest possible patch：给错误固定 id/`role=alert`，字段关联错误 id，设置选择器补标签，日期触发器名称附加“必填”。

### F-H5 `[⚠ patched, final browser verification pending]` 可见控件名称被自定义 aria-label 覆盖

- Layer：Interaction
- Severity：High（axe 对应 serious）
- Surface：排课流程、任课矩阵、课表资源选择器
- Persona：语音控制和屏幕阅读器用户

- Expected：可访问名称保留全部可见文字，状态和上下文作为屏幕阅读器补充。

结论：现在切换/合并已提交分支不会冲突，但不能把两个 worktree 直接各自整体提交后再机械合并。正确顺序应是先确定哪个方向作为基线，再按功能组挑选差异并逐组回归。

### `output/` 排除

- 所有分支的当前提交中，`git ls-tree` 均确认 `output/` 追踪文件数为 0。
- 两个活跃 worktree 的 `.gitignore` 均已加入 `/output/`。
- 仓库共享 `.git/info/exclude` 也加入 `/output/`，因此本机所有分支/worktree 立即生效。
- `git status --ignored output` 在两个 worktree 都返回 `!! output/`。
- `.git/info/exclude` 不会随仓库分发；要让远端主分支和其他开发者永久继承，仍需把当前 `.gitignore` 变更单独提交并合并。
