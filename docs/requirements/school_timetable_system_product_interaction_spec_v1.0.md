# 中小学排课系统产品与交互规格 V1.0

> 文档版本：V1.0
>
> 文档日期：2026-08-25
>
> 文档状态：目标产品基线
>
> 适用产品：单校区、中等规模中国小学与初中排课系统
>
> 历史基线：`school_timetable_system_design_v0.3.md`
>
> 视觉方向：已选定“课表画布”方向，延续现有克制、清晰的蓝色桌面端设计语言

## 1. 文档目的

本文档用于把系统从“能够维护周课表的第一阶段工具”升级为一套完整、可解释、可恢复的排课工作系统，并同时定义：

- 产品范围和业务边界；
- 核心业务对象和统一术语；
- 排课规则与约束模型；
- 自动排课、候选方案和版本模型；
- 排课前、排课中、排课后的完整工作流；
- 临时调课、请假与代课等日常运行流程；
- 五个核心工作区的功能与交互；
- 表格、课表画布、抽屉、对话框和反馈状态的统一规范；
- 业务覆盖、易用性、视觉细节和可访问性的验收标准。

V1.0 是目标产品规格，不代表当前代码已经实现本文全部能力。V0.3 文档继续保留，作为现有系统和历史架构的实施基线，不被本文件覆盖或删除。

## 2. 产品定位

### 2.1 核心问题

系统回答一个核心问题：

> 在指定学期和周循环中，把全部任课关系安排到允许使用的课节和教室，同时满足班级、教师、教室、课时和学校规则，并允许排课员理解、调整和恢复每一次结果。

### 2.2 目标学校

V1.0 以以下学校为主要验收对象：

- 单学校、单校区部署；
- 小学或初中，以固定行政班为主要教学组织；
- 18 至 36 个班级；
- 50 至 120 位教师；
- 10 至 30 门课程；
- 20 至 100 个普通教室和专用教室；
- 每周约 700 至 1,500 条课程安排；
- 由一名主要排课员负责排课，管理员处理账号和历史纠错；
- 不设置多人审核流程。

### 2.3 产品目标

1. 排课员能够从空学期或上一学期数据开始，完成全部排课准备。
2. 系统能够基于硬约束和软规则自动生成多个可比较的候选方案。
3. 所有自动结果都能解释，所有失败都能给出可处理的原因。
4. 人工调整时即时显示班级、教师、教室和规则影响。
5. 自动生成和人工调整都不会静默覆盖当前生效课表。
6. 日常临时调课、请假和代课作为日期例外处理，不污染基础周课表。
7. 历史学期和历史方案可以可靠查看、导出和复制。

### 2.4 明确不做

V1.0 不负责：

- 学生学籍、升年级、分班、转学、毕业；
- 成绩、考勤、作业和教学评价；
- 学生个人选课和个人课表；
- 招生、收费和家校沟通；
- 多学校 SaaS 租户；
- 多人审核和发布审批流；
- 自动替学校决定政策性规则。

合班、拆班和走班仅保存参与班级或教学组，不保存学生个人名单。

## 3. 产品原则

### 3.1 任务优先

导航和页面围绕排课员的工作顺序组织，不围绕数据库表组织。用户首先看到“还需要做什么”，而不是模块数量和统计卡片。

### 3.2 先解释，再执行

任何自动生成、批量修改、调课、替课和版本切换，都必须在执行前说明：

- 将影响什么；
- 为什么可以执行；
- 存在哪些风险；
- 执行后如何恢复。

### 3.3 不覆盖，只创建新结果

- 自动排课创建新的候选方案；
- 将候选方案设为当前课表时保留旧版本；
- 恢复旧版本时创建一个新版本，不修改历史版本；
- 日期例外覆盖展示结果，但不修改基础周课表。

### 3.4 硬约束绝不妥协

系统不能通过提高软规则得分来绕过硬约束。硬约束不满足时，不允许把方案设为当前课表。

### 3.5 专家高效，新手不迷路

- 新用户得到线性准备流程、推荐模板和直接修复入口；
- 熟练用户获得矩阵录入、复制粘贴、批量修改、键盘操作和局部重排；
- 高级能力按需展开，不在默认界面堆满参数。

### 3.6 状态必须可信

页面上的数量、冲突和准备状态必须来自同一数据修订版本。系统不得出现一个页面显示 0 条数据、另一个页面显示已有数据的情况。

## 4. 统一术语

V1.0 锁定以下术语，界面、接口、代码和文档不得继续混用“科目/课程”或“场地/教室”。

| 中文术语 | 英文/代码概念 | 定义 | 示例 |
| --- | --- | --- | --- |
| 课程 | Course | 学校开设的教学内容 | 数学、语文、体育 |
| 教师 | Teacher | 承担授课或代课的人 | 胡静 |
| 课节 | Item | 作息中的时间单位 | 周一第 2 节对应的“第 2 节” |
| 教室 | Room | 课程实际使用的空间资源 | 博学楼 101、物理实验室 |
| 班级 | SchoolClass | 固定行政班 | 七年级 1 班 |
| 教学组 | TeachingGroup | 合班、拆班或走班产生的排课单位 | 七年级英语 A 组 |
| 任课关系 | TeachingAssignment | 班级或教学组在学期内由谁教什么、每周几节、使用何种教室 | 七年级 1 班数学，胡静，每周 5 节 |
| 课程安排 | TimetableEntry | 某条任课关系被放入具体星期和课节的结果 | 七年级 1 班数学，周三第 2 节 |
| 规则 | Constraint | 对课程安排的硬性要求或质量偏好 | 胡静周三下午不可排课 |
| 固定安排 | FixedPlacement | 必须保留在指定位置的课程或活动 | 周一第 1 节升旗 |
| 候选方案 | ScheduleCandidate | 一次自动生成产生的可比较课表 | 均衡方案 A |
| 当前课表 | ActiveTimetableVersion | 当前供查询、导出和日常运行使用的版本 | 2026 上学期当前版本 v4 |
| 日期例外 | CalendarException | 对某个实际日期课程安排的临时覆盖 | 9 月 18 日数学调至第 6 节 |

界面中使用“任课关系”，不再使用容易与待办事项混淆的“教学任务”。迁移期间接口或旧数据库可以保留历史命名，但新代码不得继续扩散旧术语。

## 5. 信息架构

```text
排课中心
├── ① 准备检查
├── ② 课程与任课矩阵
├── ③ 规则与约束
├── ④ 方案生成
└── ⑤ 课表调整与诊断

日常运行
├── 临时调课
└── 请假与代课

基础资料
├── 教师
├── 课程
├── 教室
└── 年级与班级
```

学年、学期、作息和班级学期配置不再长期占据一级菜单，而是在“准备检查”中按当前学期组织。系统设置和用户管理继续位于系统区域。

### 5.1 全局上下文

所有业务页面顶部固定显示：

- 当前操作学年与学期；
- 当前查看的周类型或实际日期；
- 当前课表版本；
- 学期状态；
- 当前账号和角色。

切换学期只改变页面上下文，不自动改变学校的当前学期。进入历史学期时，全局上下文必须显示“历史只读”。

## 6. 核心业务对象

### 6.1 时间对象

#### 学年与学期

- 一个开放学年默认包含上学期和下学期；
- 当前课表、任课关系、规则和日期例外都明确属于一个学期；
- 历史学期默认只读；
- 学期可以从上一学期复制配置，但复制后完全独立。

#### 周循环

支持：

- 每周重复；
- 单周/双周；
- A/B 周；
- 指定教学周集合。

学校可以只启用“每周重复”，不使用高级周循环。

#### 作息模板与课节

- 可按年级组选择不同作息模板；
- 同一模板允许按星期关闭某些课节，例如周五提前放学；
- 课节包含名称、顺序、开始时间、结束时间、类型、是否允许安排课程、是否计入课时；
- 早读、午休、晚自习、班会、升旗、课间操等使用明确类型；
- 已被当前课表引用的课节不能直接删除或改变时间语义。

### 6.2 教学组织对象

#### 班级

- 属于具体学年；
- 在具体学期配置班主任、固定教室和启用状态；
- 不建立跨学年的自动升年级关系。

#### 教学组

用于表达：

- 两个或多个班级合班上课；
- 一个班拆分成多个组；
- 多个班级学生组成走班教学组；
- 不同周型由不同教学组或教师授课。

教学组只保存参与班级、名称和排课同步关系，不保存学生名单。

#### 任课关系

每条任课关系至少包含：

- 学期；
- 班级或教学组；
- 课程；
- 主教师和可选协同教师；
- 每周课时或各周型课时；
- 单次课节数；
- 连堂要求；
- 教室方式；
- 指定教室或教室类型；
- 是否允许代课；
- 状态：草稿、已确认、停用。

只有通过完整校验的已确认任课关系参与自动排课和课时完整性统计。

### 6.3 规则对象

每条规则统一包含：

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 面向人的简短名称 |
| 规则类型 | 硬约束或软规则 |
| 作用对象 | 班级、课程、教师、教室、任课关系或教学组 |
| 生效范围 | 学期、年级、班级、周型、星期或日期 |
| 条件 | 规则何时生效 |
| 要求 | 必须、不得、至少、最多、尽量等 |
| 权重 | 软规则的重要程度 |
| 来源 | 系统内置、学校模板、用户创建或复制 |
| 状态 | 草稿、启用、停用 |
| 解释文本 | 对排课结果的自然语言解释 |

### 6.4 求解与版本对象

#### 求解任务

一次自动排课是一个不可变的求解任务，保存：

- 输入数据修订号；
- 排课范围；
- 保留和锁定范围；
- 启用规则快照；
- 生成策略；
- 候选方案数量；
- 算法版本和随机种子；
- 创建人、创建时间和状态；
- 进度、失败原因和诊断结果。

#### 候选方案

一个求解任务可以产生多个候选方案。候选方案保存完整课程安排、质量评分分解、硬约束检查结果、未排课程和生成日志摘要。

#### 当前课表版本

- 一个学期同时只能有一个当前课表版本；
- 候选方案可以由排课员直接设为当前课表，不需要审批；
- 设为当前课表前必须再次验证输入修订号和硬约束；
- 旧版本转为历史版本，继续可查看和比较；
- 恢复历史版本时创建新版本，不修改历史记录。

## 7. 规则覆盖

### 7.1 硬约束

系统至少支持以下硬约束：

1. 同一班级或教学组同一时间只能有一条课程安排。
2. 同一教师同一时间只能承担一条课程安排。
3. 同一教室同一时间不能被超过容量的课程占用。
4. 教师、班级、教学组和教室的不可用时间不能排课。
5. 课程只能安排到允许教学的课节。
6. 任课关系的总课时必须完整安排。
7. 指定教室、教室类型、容量和设备要求必须满足。
8. 固定安排必须位于指定时间和位置。
9. 已锁定课程不能被自动排课或普通调整移动。
10. 合班课程必须让所有参与班级同时占用。
11. 拆班课程需要同步或按学校设置错峰安排。
12. 协同教师必须同时可用。
13. 连堂课程必须占用连续且允许连堂的课节。
14. 跨校区或远距离教室之间必须满足最短转换时间；单校区学校可关闭。
15. 教师授课资格不满足时禁止确认任课关系或排课。
16. 日期例外不能造成实际日期上的班级、教师和教室冲突。

### 7.2 软规则

系统至少支持以下软规则并允许调整权重：

1. 主课程优先安排在上午。
2. 同一课程在一周内尽量均匀分布。
3. 同一课程尽量避免同一天重复。
4. 指定课程偏好连堂或避免连堂。
5. 教师每日课时上限和连续授课上限。
6. 减少教师空堂和过长等待。
7. 平衡教师每日与每周工作量。
8. 体育课避免饭后第一节或学校指定时段。
9. 班级每天的主副课程和学习强度均衡。
10. 同一课程尽量保持教室稳定。
11. 实验课优先安排在设备可用时段。
12. 班主任课程可偏好第一节或班会相邻时段。
13. 教师个人时间偏好。
14. 课程安排与教研活动避让。
15. 指定课程之间保持最小间隔。

### 7.3 规则模板

系统内置以下模板作为起点：

- 普通初中推荐模板；
- 普通小学推荐模板；
- 主课程均衡模板；
- 教师体验优先模板；
- 教室资源紧张学校模板。

模板只能创建学校自己的规则副本，后续模板更新不得静默修改已在使用的学校规则。

### 7.4 规则冲突诊断

保存规则和生成方案前，系统必须检测：

- 两条硬约束直接矛盾；
- 可用容量明显不足；
- 规则作用范围为空；
- 规则对象已停用；
- 连堂要求超过连续可用课节；
- 固定安排之间互相冲突；
- 单双周配置与任课课时不一致。

提示必须使用自然语言，并给出直接修复入口。

## 8. 端到端工作流

### 8.1 新学期准备

```text
选择或创建学期
→ 复制上一学期配置或从空白开始
→ 配置年级、班级、教师、课程和教室
→ 配置作息、班主任和固定教室
→ 填写课程与任课矩阵
→ 配置规则与固定安排
→ 运行准备检查
→ 进入方案生成
```

### 8.2 自动排课

```text
选择排课范围
→ 选择保留、锁定和清空范围
→ 选择生成策略和候选数量
→ 运行生成前检查
→ 创建求解任务
→ 查看生成进度
→ 对比候选方案
→ 选择一个方案进入调整
→ 设为当前课表
```

### 8.3 人工调整

```text
选择班级/教师/教室视角
→ 选择课程安排
→ 查看可移动位置和诊断
→ 预览影响范围和质量变化
→ 应用移动、交换、锁定或删除
→ 撤销/重做或保存新版本
```

### 8.4 日常临时变化

```text
选择实际日期
→ 选择原课程或录入请假
→ 系统查找受影响课程
→ 推荐调课、换课、代课或换教室方案
→ 预览冲突与通知清单
→ 保存日期例外
```

## 9. 核心页面规格

### 9.1 准备检查

#### 页面目标

告诉排课员当前学期是否具备生成方案的条件，以及下一步应该修复什么。

#### 页面结构

1. 紧凑的当前学期上下文；
2. 五阶段进度：准备检查、课程与任课矩阵、规则与约束、方案生成、课表调整与诊断；
3. 总结状态：可以生成、有提醒或无法生成；
4. 按业务分组的检查清单；
5. 最近方案摘要。

#### 检查分组

- 基础资料；
- 学期与作息；
- 年级和班级；
- 任课关系；
- 教师可用性；
- 教室容量与设备；
- 固定安排和硬约束；
- 软规则；
- 理论容量与显然不可行检查。

#### 状态语义

| 状态 | 行为 |
| --- | --- |
| 通过 | 不要求处理，可展开查看依据 |
| 提醒 | 允许继续，但说明可能降低的质量 |
| 阻塞 | 禁止生成，必须提供直接修复入口 |

点击问题时，在右侧抽屉或对应工作区打开修复界面。保存后返回原检查位置并自动重新运行受影响的检查，不刷新整页。

#### 禁止事项

- 不展示与排课无关的访问量或装饰性统计；
- 不把所有检查结果做成独立卡片；
- 不使用只显示错误代码的提示；
- 不在页面标题旁放大量操作按钮。

### 9.2 课程与任课矩阵

#### 页面目标

以最低操作成本完成全校任课关系录入和校验。

#### 默认视图

默认使用“班级 × 课程矩阵”：

- 行为班级；
- 列为课程；
- 单元格显示教师、每周课时、教室方式和异常状态；
- 固定行列，支持横向与纵向滚动；
- 年级和班级数量大时按年级分页或分组加载。

#### 单元格交互

- 单击：选择并在右侧显示详情；
- 双击或 Enter：打开轻量编辑浮层；
- 支持复制、粘贴和填充相邻单元格；
- 支持多选后批量设置教师、课时、教室方式和周型；
- 支持从上一学期复制整班或整年级；
- 修改后即时执行容量、重复教师和资格校验。

#### 其他视角

同一数据提供：

- 班级视角；
- 教师视角；
- 课程视角；
- 教室视角；
- 普通分页表格视角。

视角切换不改变数据，只改变组织方式和筛选条件。

#### 导入

支持 UTF-8 CSV 和 XLSX：

1. 上传；
2. 字段映射；
3. 预检；
4. 逐行错误；
5. 预览新增和修改；
6. 确认提交；
7. 返回结果摘要。

重复提交必须幂等，预检后数据发生变化时要求重新预检。

### 9.3 规则与约束

#### 页面目标

让排课员用业务语言建立规则，并能够理解规则影响和相互冲突。

#### 页面结构

- 左侧：硬约束、软规则、固定安排、模板；
- 中间：自然语言规则列表；
- 右侧：选中规则的作用范围、时间网格、强度、权重和影响摘要；
- 顶部工作区工具栏：新建规则、应用模板、复制上一学期、批量启停。

没有筛选条件或操作时，不渲染空工具栏。

#### 新建规则流程

```text
选择规则类型
→ 选择作用对象和范围
→ 选择时间或条件
→ 设置硬约束/软规则及权重
→ 查看自然语言预览
→ 查看影响数量和冲突
→ 保存
```

#### 时间网格交互

- 点击单格切换状态；
- 拖动可批量涂选；
- 支持整行、整列、上午、下午和整天选择；
- 状态同时使用颜色、图标和文字；
- 支持复制给多个教师、班级或教室；
- 复制前预览覆盖范围，不静默替换已有规则。

### 9.4 方案生成

#### 页面目标

把自动排课变成可控、可解释、可取消、可比较的过程。

#### 第一步：选择范围

- 全校、年级、班级或任课关系；
- 全量重排或填补未排课程；
- 保留当前课程安排；
- 选择要清空的范围；
- 保留全部锁定课程；
- 保存为可复用范围模板。

#### 第二步：生成策略

- 均衡质量；
- 班级课程分布优先；
- 教师体验优先；
- 教室利用优先；
- 自定义权重；
- 生成 1 个或 3 个候选方案。

策略只调整软规则权重，不能关闭必要硬约束。

#### 第三步：检查并生成

显示：

- 排课范围和任课关系数量；
- 预计安排课节数量；
- 锁定和固定安排数量；
- 硬约束、软规则和待确认问题；
- 输入数据修订时间；
- 预计用时；
- “生成不会覆盖当前课表”的明确说明。

#### 求解进度

求解任务状态：

```text
等待中 → 检查输入 → 构建约束 → 寻找可行解 → 优化质量 → 生成候选 → 完成
```

用户可以离开页面，后台继续运行。返回后恢复进度。允许取消尚未完成的任务；取消不能留下部分课表。

#### 无解诊断

失败时必须展示尽可能小的冲突集合和可执行建议。例如：

> 七年级体育共有 24 节，但体育教师和操场共同可用的容量只有 20 节，至少缺少 4 个课节。建议增加操场可用时间、减少教师禁排时间或调整体育任课关系。

禁止仅显示“排课失败”“无可行解”或算法异常代码。

#### 候选方案对比

候选方案并排比较：

- 是否完整排满；
- 硬冲突数量；
- 综合质量分；
- 主课程上午比例；
- 同科分布均匀度；
- 教师空堂数量；
- 连续授课超出偏好数量；
- 教室稳定性；
- 相对当前课表的变化数量。

综合分必须可以展开查看分项，不允许只有无法解释的单一分数。

### 9.5 课表调整与诊断

#### 页面目标

在同一工作空间完成查看、移动、交换、锁定、诊断、撤销和局部重排。

#### 页面布局

- 左侧：应用导航；
- 顶部第一行：班级/教师/教室视角、对象选择器、前后切换和健康摘要；
- 顶部第二行：独立工具栏，包含撤销、重做、剪切、复制、删除、锁定、批量调整和保存版本；
- 中央：周课表画布；
- 右侧：固定宽度诊断面板；
- 页面标题区域保持紧凑，不放业务操作按钮；
- 表头只表示星期和字段，不承载按钮。

#### 课程格内容

最少显示：

- 课程；
- 教师；
- 教室；
- 锁定或临时状态；
- 周型差异。

课程颜色用于帮助识别课程，不承担冲突语义。冲突、警告和锁定必须另外使用图标、文字和边框。

#### 选择与移动

支持两种等价方式：

1. 拖动课程到目标位置；
2. 选择课程，再选择目标位置。

开始移动后：

- 可用位置显示明确可用标记；
- 不可用位置可以点击查看原因；
- 目标位置已有课程时，系统判断是否可以交换；
- 右侧实时显示硬冲突、软规则变化和影响对象；
- 应用前显示最终动作摘要。

#### 诊断面板

选中课程后显示：

- 当前课程安排；
- 班级、教师和教室可用性；
- 关联锁定和固定安排；
- 当前硬冲突；
- 软规则提醒和得分影响；
- 推荐移动位置；
- 影响的班级、教师、教室和课程安排；
- 应用调整或忽略建议。

文案示例：

- “不可移动：胡静在周四第 3 节已有课程。”
- “可以移动：无硬冲突，软规则分数降低 2 分。”
- “推荐周二第 2 节：减少 1 个教师空堂，质量分增加 3 分。”

#### 撤销与版本

- 当前编辑会话支持多步撤销和重做；
- 保存创建新方案版本；
- 自动保存编辑草稿，但不自动替换当前课表；
- 离开未保存编辑会话时明确提示；
- 多人并发修改时拒绝旧数据覆盖，并提供刷新和另存为副本。

#### 局部重排

用户可以框选班级、日期范围、课程或问题集合，选择“仅重新生成选中范围”。未选择范围和锁定课程保持不变。

## 10. 日常运行

### 10.1 临时调课

#### 数据原则

临时调课创建日期例外，不直接修改基础周课表。

#### 调整类型

- 移动课程；
- 两节课程交换；
- 临时更换教师；
- 临时更换教室；
- 停课；
- 补课；
- 临时活动占用。

#### 交互流程

```text
选择实际日期
→ 选择原课程
→ 选择调整类型
→ 查看系统推荐
→ 选择目标时间/教师/教室
→ 预览冲突、影响和通知清单
→ 填写原因
→ 保存日期例外
```

实际日期课表默认叠加显示基础周课表和日期例外，并清晰区分“原安排”和“临时安排”。

### 10.2 请假与代课

#### 请假记录

至少包含：

- 教师；
- 开始和结束日期时间；
- 请假类型；
- 原因或备注；
- 是否影响早读、晚自习和活动；
- 状态。

#### 受影响课程

保存请假前即时列出受影响课程。系统不得等到保存后才告诉用户影响范围。

#### 代课推荐

推荐依据：

- 教师是否具备课程资格；
- 目标时间是否可用；
- 当日和当周工作量；
- 连续授课情况；
- 是否需要换教室；
- 同课程、同年级或同教研组优先级；
- 历史代课公平性。

每个推荐必须显示理由，不只显示一个排序分数。排课员可以逐节处理或批量采用推荐。

## 13. 通用交互规范

### 13.1 页面层级

每个页面最多包含：

1. 全局上下文栏；
2. 工作区工具栏；
3. 主内容；
4. 按需出现的右侧详情/诊断面板。

不使用占据大量高度的重复标题和说明区。没有筛选条件时不显示筛选容器；没有操作时不显示空工具栏。

### 13.2 按钮位置

- 页面标题旁不放业务按钮；
- 表格列头内不放业务按钮；
- 新增、导入、批量操作等按钮位于表格或工作区上方的独立工具栏；
- 多个按钮按主操作、次操作、更多操作分组；
- 危险操作收纳到“更多”并与普通操作分隔。

### 13.3 表格与分页

所有潜在出现大量数据的普通表格必须支持分页。

统一要求：

- 默认每页 20 条；
- 可选 20、50、100 条；
- 显示总数、当前范围和页码；
- 支持上一页、下一页和直接跳转；
- 筛选、排序和分页由服务端执行；
- 切换详情后返回时保留筛选、排序和页码；
- 删除当前页最后一条后自动回到有效页；
- 分页加载失败时保留现有数据并允许重试；
- URL 保存可分享的筛选和页码状态。

矩阵和课表画布不使用普通分页时，必须采用分组加载、虚拟滚动或按年级切换，避免一次渲染全校数据。

### 13.4 表单

- 标签不使用仅占位符方式；
- 必填项显示原因，而不只显示星号；
- 本地即时校验与服务端最终校验一致；
- 错误出现在字段附近，并在顶部提供错误摘要；
- 保存失败保留用户输入；
- 长表单按业务分组，右侧显示实时影响或预览；
- 简单编辑使用浮层或抽屉，复杂流程使用独立页面。

### 13.5 反馈状态

每个页面必须设计：

- 首次加载；
- 无数据；
- 无筛选结果；
- 部分加载失败；
- 完全失败；
- 保存中；
- 保存成功；
- 校验失败；
- 并发冲突；
- 权限不足；
- 历史只读；
- 后台任务运行中；
- 后台任务失败和恢复。

成功提示不应遮挡后续操作；失败提示必须包含重试或修复入口。

### 13.6 防错与恢复

- 普通编辑尽可能支持撤销；
- 批量操作必须先预览影响；
- 删除、清空、覆盖和切换当前版本需要明确确认；
- 确认文案写清对象和数量，不使用“是否确定”；
- 网络失败后不得产生无法判断是否成功的状态；
- 重复提交使用幂等键；
- 并发冲突不得静默覆盖；
- 自动保存草稿不得自动设为当前课表。

### 13.7 键盘与专家操作

核心桌面端操作支持：

- 方向键移动课表焦点；
- Enter 打开详情或编辑；
- Space 选择；
- Ctrl/Cmd+C、V 复制粘贴；
- Ctrl/Cmd+Z、Shift+Ctrl/Cmd+Z 撤销重做；
- Delete 删除未锁定课程；
- `/` 聚焦搜索；
- `?` 打开快捷键帮助。

所有快捷键都必须有等价的可见操作。

## 14. 视觉与细节规范

### 14.1 视觉方向

采用已选定的“课表画布”方向：

- 克制的暖白/白色基础表面；
- 钴蓝色作为主要操作色；
- 近黑正文和高对比中性色；
- 课程使用低饱和辅助色；
- 以留白、对齐、字号和分隔线建立层级；
- 少量圆角，不使用卡片套卡片；
- 阴影只用于浮层、拖拽和需要表达层级的对象。

### 14.2 桌面布局

- 左侧导航展开宽度约 240 至 256px，折叠宽度约 64px；
- 全局上下文栏高度约 56px；
- 工作区工具栏高度约 48 至 56px；
- 调整页右侧诊断面板宽度约 320 至 360px；
- 主内容优先占用剩余空间；
- 不为装饰性标题预留大块空白。

### 14.3 字体与控件

- 正文 14 至 16px；
- 表格和课表最小正文 13px，仅辅助信息可使用；
- 常用按钮高度不低于 40px；
- 触控或移动端目标不低于 44px；
- 行高保证中文易读；
- 数字、星期和时间保持稳定对齐。

### 14.4 颜色语义

颜色不能单独承担状态：

| 状态 | 视觉组合 |
| --- | --- |
| 成功/可用 | 绿色 + 对勾 + 文字 |
| 提醒/软规则 | 橙色 + 提醒图标 + 原因 |
| 冲突/阻塞 | 红色 + 错误图标 + 原因 |
| 锁定 | 锁图标 + 文字或边框 |
| 选中 | 蓝色高对比边框 + 焦点状态 |
| 禁用 | 中性色 + 禁用说明 |

### 14.5 动效

- 普通状态切换 120 至 180ms；
- 抽屉和浮层 180 至 240ms；
- 拖拽使用轻微抬升和目标吸附；
- 求解进度使用真实阶段，不播放虚假进度；
- 支持 `prefers-reduced-motion`；
- 动画可被用户输入打断，不阻塞操作。

### 14.6 响应式

- 完整排课和矩阵编辑以桌面端为主要目标；
- 平板可以查看、筛选和进行简单调整；
- 手机端提供课表查看、临时调课确认和代课处理，不提供全校矩阵和复杂自动排课配置；
- 小屏幕不得简单压缩桌面课表导致文字不可读。

### 14.7 可访问性

目标符合 WCAG 2.2 AA：

- 完整键盘可操作；
- 可见焦点；
- 文本和控件对比度达标；
- 图标按钮有可访问名称；
- 表格、网格和课表具备正确语义；
- 屏幕阅读器可以读出课程、教师、教室、时间和状态；
- 错误不只使用颜色；
- 缩放至 200% 后核心任务仍可完成。

## 15. 数据一致性、并发和恢复

### 15.1 修订一致性

准备状态、求解输入和候选方案必须引用明确的数据修订号。以下数据变化会使尚未开始的旧求解配置失效：

- 任课关系；
- 作息与课节；
- 教师、班级和教室可用性；
- 硬约束；
- 固定安排；
- 当前课表锁定状态。

求解过程中数据变化时，已开始任务可以基于输入快照完成，但结果必须标记“基于旧数据”，不能直接设为当前课表。

### 15.2 并发编辑

- 所有写入使用强 ETag 或等价修订控制；
- 旧页面提交返回并发冲突，不静默覆盖；
- 用户可以查看差异、刷新或另存为副本；
- 同一当前课表编辑会话可以提供软锁提示，但数据库约束和版本检查是最终保护。

### 15.3 自动排课恢复

- 求解任务在后台执行；
- 页面关闭不终止任务；
- 服务重启后任务可以恢复或明确失败；
- 重试创建新尝试并保留原失败记录；
- 候选方案只有完整写入后才可见；
- 不允许展示半张候选课表。

### 15.4 新系统迁移策略

当前项目尚未进入真实生产使用时，V1.0 领域结构应整理为干净的基线 Migration：

- 删除仅为早期错误模型服务且尚未部署的迁移链；
- 不保留无意义的“创建后立即改名、加列、删列”迁移；
- 新增规则、求解、候选、版本、日期例外、请假和代课表时统一设计外键、唯一约束和索引；
- 基线正式部署后只允许增量 Migration，不重写已部署历史。

任何 Migration 整理必须先确认部署状态和备份，不得直接删除已在真实环境执行的迁移。

## 16. 质量评分与可解释性

### 16.1 质量分组成

综合质量分为 0 至 100，仅用于候选方案之间比较。必须同时展示：

- 课程分布；
- 教师体验；
- 班级负荷；
- 连堂和间隔；
- 教室稳定性；
- 学校自定义规则。

硬约束不计入加权总分。任何硬约束失败都使方案不可用。

### 16.2 解释要求

系统必须能回答：

- 为什么这节课安排在这里；
- 为什么不能移动到某个位置；
- 为什么候选 A 比候选 B 得分高；
- 哪些规则没有满足；
- 哪些课程未排以及原因；
- 哪条规则导致无解；
- 调整后哪些对象受到影响。

### 16.3 推荐行为

推荐结果显示理由、收益和代价。例如：

> 推荐移动到周四第 2 节。班级、教师和教室均可用；减少胡静 1 个空堂；数学仍保持隔日分布；七年级 1 班当天主课程增加至 4 节。

## 17. 性能与规模验收

以 24 个班级、80 位教师、20 门课程、60 个教室、约 1,000 条每周课程安排为基准：

- 普通列表首屏在正常校园网络下 1 秒内出现可用内容；
- 切换班级、教师或教室课表的感知响应不超过 300ms；
- 单次移动的本地反馈即时出现，服务端冲突结果目标不超过 500ms；
- 矩阵滚动保持流畅，不一次渲染全校全部单元格；
- 普通表格使用服务端分页；
- 自动排课 1 秒内返回任务已创建和初始阶段；
- 中等规模全校方案生成目标在 5 分钟内完成，期间持续提供真实进度；
- 导出任务较大时转为后台任务并通知完成；
- 任何性能降级不得通过减少冲突检查或跳过数据一致性换取。

## 18. 10/10 验收标准

### 18.1 业务覆盖

必须通过以下真实场景：

1. 从上一学期复制并重新确认任课关系。
2. 从空白建立 24 个班级的任课矩阵。
3. 配置教师、班级、教室不可用时间和固定安排。
4. 处理连堂、合班、拆班和单双周课程。
5. 生成至少 3 个无硬冲突候选方案。
6. 解释未满足软规则和无解原因。
7. 锁定部分课程后局部重排。
8. 在班级、教师和教室视角人工移动并即时诊断。
9. 将候选方案设为当前课表并保留历史版本。
10. 创建日期临时调课，不改变基础周课表。
11. 录入教师请假并批量安排代课。
12. 查看和导出班级、教师、教室、历史和实际日期课表。

### 18.2 易用性

- 第一次使用的排课员不阅读技术文档也能完成准备检查；
- 每个阻塞问题都有原因和直接修复入口；
- 每个未排课程都有明确原因；
- 每次移动都能看到影响范围；
- 每个自动结果都可以解释；
- 每次批量操作都可以预览；
- 每次重要修改都可以撤销或恢复版本；
- 页面不存在必须依赖鼠标悬停才能发现的关键功能；
- 新手路径清晰，专家操作不被多余向导阻挡；
- 用户不会因为切换学期、视角或分页丢失工作上下文。

### 18.3 视觉与细节

- 页面标题和说明不无意义占据首屏；
- 操作按钮位于工作区或表格上方独立工具栏；
- 表头保持纯粹；
- 所有大量数据表格支持分页；
- 课表画布在常见 1440×900 和 1920×1080 桌面尺寸下可读；
- 课程、教师、教室、时间和状态层级明确；
- 状态不只依赖颜色；
- 折叠导航无溢出、裁切和残留文字；
- 加载、空状态、错误、并发、只读和后台任务状态完整；
- 键盘、缩放、减少动效和屏幕阅读器行为达到既定标准。

### 18.4 信任与安全

- 当前课表不会被自动生成静默覆盖；
- 历史课表不会被当前学期操作修改；
- 硬冲突方案不能设为当前课表；
- 数据修订不一致时结果明确标记过期；
- 并发写入不会静默覆盖；
- 日期例外不会污染基础周课表；
- 所有关键操作可追踪；
- 不存在无法判断提交是否成功的半完成状态。

## 20. 完成定义

V1.0 不是“页面已经画完”，而是以下闭环全部成立：

> 每条任课关系可验证，每条规则可理解，每次生成可追踪，每个结果可解释，每次调整可预览，每个错误可修复，每个版本可恢复，每个实际日期变化不破坏基础课表。

只有产品、数据模型、求解服务、交互、视觉、测试和运维共同满足本规格，才能称为 V1.0 完成。
