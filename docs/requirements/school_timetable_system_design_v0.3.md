# 小学与初中排课系统需求设计文档（第一阶段）

> 文档版本：V0.3  
> 文档日期：2026-08-21  
> 文档状态：第一阶段可实施需求基线  
> 对应架构：`school_timetable_system_architecture_design_v0.4.md`  
> 上一版本：V0.2

## 1. 文档目的

本文档用于明确小学、初中排课系统第一阶段的业务边界、核心对象、时间模型、学年学期模型、排课规则和基础功能。

V0.3 在上一版基础上固定了“单学校部署、第一阶段仅手工排课、每学期统一作息”的范围，并补齐学期班级配置、生命周期、历史数据语义、权限、CSV 导入边界和已有课表后的修改规则。

第一阶段不追求覆盖学校管理中的全部场景，而是先完成一个结构清晰、能够实际维护普通周课表的最小可用版本。

系统只负责回答以下问题：

> 在某个学年、某个学期，学校有哪些班级、教师、课程和教室，以及每个班在什么时间、由哪位教师、在哪里上什么课。

系统暂不负责学生学籍、学生升年级、重新分班、转学、留级和毕业管理。

---

## 2. 已确认的设计范围

### 2.1 第一阶段包含

- 系统以“一套部署服务一所学校”为边界，不在同一数据库中混合多所学校数据。
- 使用本地账号密码登录，支持管理员、排课员和只读查看者三类角色。
- 管理学年和学期。
- 第一阶段一个开放学年恰好包含上学期和下学期两个学期，不支持第三学期或暑期学期。
- 班级属于具体学年。
- 同一学年内，上下学期共用同一批班级身份，但固定教室和班主任按学期配置。
- 教学任务属于具体学期。
- 排课结果属于具体学期。
- 系统设置一个学校级当前学期，并由它派生当前学年，作为默认操作范围。
- 可以切换到历史学年、历史学期查看课表。
- 新学年重新创建或导入该学年的班级，不执行自动升年级。
- 新学年的班级数量、班级编号、固定教室和师资配置可以与上一学年不同。
- 新学期可以参考或复制上一学期的教学任务，并以草稿形式重新确认。
- 只设计普通教学周，课表按周循环。
- 学生以固定行政班为排课单位。
- 每个班可以在具体学期设置固定教室和班主任。
- 普通课程默认在该班本学期固定教室上课。
- 支持特殊教室，例如操场、音乐教室、美术教室、实验室和计算机教室。
- 支持完整学校作息，包括早操、早读、普通课程、课间操、课间活动、午休和晚自习等课节。
- 晚自习为可选课节，默认不作为正式课程，不计入普通课程课时。
- 系统能够判断同一学期内的班级、教师和教室冲突。
- 系统能够检查各教学任务的每周课时是否排满。
- 第一阶段只实现手工排课，不实现自动生成课表。
- 班级批量导入和课表导出统一使用 UTF-8 CSV；浏览器打印不作为独立文件格式。

### 2.2 第一阶段暂不包含

- 学生名单和学籍档案。
- 学生升年级、毕业、留级、跳级和转学。
- 新生分班和学生重新分班。
- 新旧学年班级之间的继承、映射或追踪关系。
- 自动判断“上一学年的某班”对应“下一学年的哪个班”。
- 单周、双周和指定教学周。
- 教学组、分层教学、合班和拆班。
- 小学和初中的不同排课规则。
- 不同年级、不同班级或不同星期使用不同课节。
- 独立的固定活动管理模块。
- 教师请假、代课、临时调课和停课。
- 考试周、活动周和节假日调休。
- 早读、晚自习的教师值班安排。
- 学生个人选课。
- 多校区和跨校区交通时间。
- 复杂的教师工作量公平优化。
- 自动排课和优化评分。
- 课表发布、版本审批和历史文本快照。
- 同一数据库服务多所学校的 SaaS 多租户。
- 用户自助注册、邮件找回密码和单点登录。
- XLSX、PDF 等专用导入导出格式。

> 说明：早操、课间操、课间活动等虽然属于学校固定安排，但第一阶段不单独建立“固定活动”业务模块，只把它们作为学校作息中的不可排普通课程课节。

### 2.3 系统边界

本系统是排课系统，不是学籍系统。

新学年开始前，学校已经完成年级设置、班级设置和人员安排。排课系统只接收并维护当前学年的结果，例如：

```text
2027—2028学年
- 七年级1班
- 七年级2班
- 八年级1班
- 八年级2班
- 八年级3班
- 九年级1班
```

系统不需要知道：

- 2026—2027学年的七年级1班是否变成了八年级1班；
- 原班学生进入了哪个新班；
- 某个班为何增加、减少、拆分或合并；
- 某位学生是否转班、留级或转学。

因此，班级在不同学年之间相互独立，不建立自动升年级关系。

### 2.4 第一阶段实施假设

以下假设是第一阶段能够按当前模型实施的前提；目标学校不满足时，应先调整需求和数据模型，不能在实现阶段用临时代码绕过：

1. 一个部署实例只服务一所学校。
2. 同一学期内，全校所有年级和班级使用同一套课节。
3. 所有启用的星期使用同一组课节；第一阶段不支持“周五提前放学”等按星期变化的作息。
4. 一个教室在同一课节最多容纳一个班。操场等可共享区域需要拆成“操场A区”“操场B区”等独立教室后参与排课。
5. 第一阶段以人工选择和移动课程为主，系统只负责硬约束校验和课时完整性检查。
6. 当前学期是学校级默认入口，不是每个用户的个人偏好；用户查看历史学期不会改变系统当前学期。
7. CSV 导入采用“预检后提交”：预检返回逐行错误，只有全部有效或用户确认提交有效行后才写入；具体策略必须在导入页面明确显示。

## 3. 系统目标

第一阶段系统需要解决以下核心问题：

1. 当前操作的是哪个学年、哪个学期。
2. 当前学年有哪些年级和班级。
3. 学校一天有哪些课节。
4. 当前学期每个班需要上哪些课程，每周分别上多少节。
5. 每门课由哪位教师负责，在哪里上课。
6. 如何把课程安排到一周的可用课节中。
7. 如何避免班级、教师和教室发生冲突。
8. 如何保留并查看历史学期课表，避免新学期数据覆盖旧数据。

系统的核心业务可以概括为：

> 在选定学期内，将教学任务安排到允许排课的课节中，同时满足班级、教师、教室和每周课时约束。

## 4. 核心业务概念

### 4.1 学年

学年是管理班级和学期的上层时间范围，例如：

```text
2026—2027学年
2027—2028学年
```

建议字段：

| 字段     | 说明                |
| -------- | ------------------- |
| 学年ID   | 系统唯一标识        |
| 学年名称 | 例如“2026—2027学年” |
| 开始日期 | 学年开始日期        |
| 结束日期 | 学年结束日期        |
| 状态     | 草稿、开放、已关闭  |

基本规则：

- 班级必须属于一个具体学年。
- 一个学年可以包含多个班级。
- 第一阶段一个开放学年恰好包含上学期和下学期两个学期；草稿准备期间可以暂时未创建完整，但不能创建第三个学期。
- 当前学年由学校级当前学期所属学年派生。
- 已结束学年的历史数据不能被新学年数据覆盖。

---

### 4.2 学期

学期是教学任务和排课结果的直接时间范围。

例如：

```text
2026—2027学年
├── 上学期
└── 下学期
```

建议字段：

| 字段     | 说明               |
| -------- | ------------------ |
| 学期ID   | 系统唯一标识       |
| 所属学年 | 对应学年ID         |
| 学期名称 | 上学期或下学期     |
| 学期顺序 | 1或2，用于排序     |
| 开始日期 | 学期开始日期       |
| 结束日期 | 学期结束日期       |
| 状态     | 草稿、开放、已关闭 |

基本规则：

- 每个学期只能属于一个学年。
- 学期顺序只能为1或2，同一学年各一条，分别表示上学期和下学期。
- 学期创建后所属学年、名称和顺序不可修改；完全空的误建草稿应删除后按正确顺序重建，不能通过交换顺序改写学期身份。
- 教学任务必须属于一个具体学期。
- 排课结果必须属于一个具体学期。
- 学校级设置同一时间只能指向一个当前学期。
- 当前学期只是系统默认入口，不代表只能查看当前学期。
- 历史学期应允许查看，但默认不允许直接覆盖或修改其课表。

---

### 4.3 年级

年级用于组织和管理班级，例如：

- 一年级；
- 二年级；
- 七年级；
- 八年级。

年级本身可以作为全校通用的基础字典，不需要每学年重复创建。班级通过“所属学年 + 所属年级”确定其实际归属。

建议字段：

| 字段     | 说明         |
| -------- | ------------ |
| 年级ID   | 系统唯一标识 |
| 年级名称 | 例如“七年级” |
| 排序号   | 控制显示顺序 |
| 是否启用 | 是否仍在使用 |

第一阶段中，年级主要用于分类、筛选和展示，不直接参与排课冲突判断。

---

### 4.4 班级

班级是学生参与排课的基本单位，例如“七年级1班”。

班级必须属于一个具体学年和一个年级。

建议字段：

| 字段     | 说明                      |
| -------- | ------------------------- |
| 班级ID   | 系统唯一标识              |
| 所属学年 | 对应学年ID                |
| 所属年级 | 对应年级ID                |
| 班级名称 | 例如“七年级1班”           |
| 班级编号 | 例如“1班”，用于排序和导入 |
| 状态     | 正常、停用                |

基本规则：

- 同名班级可以在不同学年重复出现。
- 同一学年内，班级名称不能重复。
- 同一学年内，上下学期共用同一条班级身份记录。
- 固定教室和班主任不保存在班级身份记录中，而是保存在“学期班级配置”中。
- 下一学年的同名或相邻年级班级是新的独立记录。
- 系统不记录两个学年班级之间是否为同一批学生。
- 已经被历史教学任务或课表引用的班级不能物理删除，只能停用。

示例：

```text
班级ID：C-2026-0701
学年：2026—2027学年
年级：七年级
班级名称：七年级1班
```

```text
班级ID：C-2027-0801
学年：2027—2028学年
年级：八年级
班级名称：八年级1班
```

以上两条记录相互独立，系统不自动认为它们存在升年级或继承关系。

---

### 4.4.1 学期班级配置

学期班级配置描述某个学期中一个班级的默认教室和班主任。它不创建新的班级身份，只为同一学年内共享的班级补充学期级设置。

建议字段：

| 字段           | 说明             |
| -------------- | ---------------- |
| 学期班级配置ID | 系统唯一标识     |
| 所属学期       | 对应学期ID       |
| 班级ID         | 对应本学年班级   |
| 固定教室       | 可选，对应教室ID |
| 班主任         | 可选，对应教师ID |
| 状态           | 正常、停用       |

基本规则：

- `学期 + 班级`只能存在一条配置。
- 班级所属学年必须与学期所属学年一致。
- 班级参与某学期的教学任务前，必须存在该学期的班级配置；固定教室和班主任字段可以为空。
- 上学期和下学期可以使用不同固定教室和班主任。
- 创建下学期时可以复制上学期配置，但复制后是独立数据。
- 普通课程使用“教学任务所属学期”的班级固定教室，不能读取其他学期配置。
- 已关闭学期的配置只读；修改新学期配置不能影响历史学期。
- 班级没有固定教室且教学任务也没有指定教室时，系统必须拒绝排课。

---

### 4.5 课程

课程表示学校开设的课程，例如：

- 语文；
- 数学；
- 英语；
- 体育；
- 音乐；
- 美术；
- 信息技术。

第一阶段不强制区分主科、副科或活动课程。

建议字段：

| 字段     | 说明                   |
| -------- | ---------------------- |
| 课程ID   | 系统唯一标识           |
| 课程名称 | 例如“数学”             |
| 课程简称 | 可选，用于课表紧凑显示 |
| 是否启用 | 是否仍在使用           |

已经被历史教学任务引用的课程不应物理删除，只能停用。

---

### 4.6 教师

教师是教学任务的授课资源。

一位教师可以：

- 教多个班；
- 教一个或多个课程；
- 同时担任班主任。

系统不能将教师与课程设计成一对一关系。

建议字段：

| 字段     | 说明                     |
| -------- | ------------------------ |
| 教师ID   | 系统唯一标识             |
| 教师姓名 | 教师名称                 |
| 教师编号 | 可选，便于区分同名教师   |
| 是否启用 | 是否在职或参与新学期排课 |

建议增加教师与课程的关联表：

| 字段   | 说明               |
| ------ | ------------------ |
| 教师ID | 对应教师           |
| 课程ID | 该教师可教授的课程 |

该关联主要用于录入校验和筛选，不代表教师永久负责某个班。

真正的任课关系由某个具体学期的教学任务决定。例如：

```text
2026—2027上学期：七年级1班数学由张老师负责
2026—2027下学期：七年级1班数学由李老师负责
```

教师停用后，不能再参与新教学任务，但其历史课表仍应正常显示。

---

### 4.7 教室

教室表示课程或活动发生的位置。

教室可以分为：

- 普通教室；
- 操场；
- 音乐教室；
- 美术教室；
- 实验室；
- 计算机教室；
- 其他功能教室。

建议字段：

| 字段     | 说明                   |
| -------- | ---------------------- |
| 教室ID   | 系统唯一标识           |
| 教室名称 | 例如“教学楼201”        |
| 教室类型 | 普通教室、操场、机房等 |
| 是否启用 | 是否可以用于新排课     |

第一阶段不计算教室人数容量和设备条件，并把每一条教室记录视为同一课节只能被一个班占用。需要同时使用的大型教室必须拆成多个可独立占用的区域记录。

已经被历史班级或课表引用的教室不应物理删除，只能停用。

---

### 4.8 作息模板

作息模板描述某个学期内学校每天的时间结构。

例如：

- 早操；
- 早读；
- 上午第1节；
- 上午第2节；
- 课间操；
- 上午第3节；
- 上午第4节；
- 午休；
- 下午第1节；
- 下午第2节；
- 课间活动；
- 下午第3节；
- 晚自习1；
- 晚自习2。

第一阶段中，每个学期最多创建一套全校作息模板；`draft`学期准备期间可以暂时没有模板，但转为`open`前必须存在且只有一套结构完整的模板。该模板适用于全校所有年级、班级和启用星期，所有启用星期共享同一组课节。上下学期作息相同时，可以复制上一学期模板；作息发生变化时，可以独立修改新学期模板，不影响历史学期。

建议字段：

| 字段       | 说明                                       |
| ---------- | ------------------------------------------ |
| 作息模板ID | 系统唯一标识                               |
| 所属学期   | 对应学期ID                                 |
| 模板名称   | 例如“2026—2027上学期作息”                  |
| 适用星期   | 第一阶段默认周一至周五；只能启用或停用整天 |

作息模板负责定义“学校一天有哪些课节”，但不负责定义某个班在该课节具体上什么课。第一阶段不支持按年级、班级或星期配置不同的课节集合。

模板必须为星期一至星期日各保存一条启用配置，至少启用一天，并至少包含一个已启用的普通课程课节；未满足这些条件的学期不能转为`open`。

---

### 4.9 课节

课节是排课系统中的时间基础单位。

不能只使用“第几节”表示时间，因为早操、早读、课间操、午休和晚自习不一定属于普通课程节次。因此，每个课节必须拥有独立的课节ID。

建议字段：

| 字段                 | 说明                           |
| -------------------- | ------------------------------ |
| 课节ID               | 系统唯一标识                   |
| 所属作息模板         | 对应作息模板ID                 |
| 课节名称             | 早读、上午第1节、课间操等      |
| 课节类型             | 普通课程、固定非课程、自习管理 |
| 开始时间             | 例如08:00                      |
| 结束时间             | 例如08:45                      |
| 排序号               | 决定一天中的展示顺序           |
| 是否允许排普通课程   | 普通课程能否安排在该课节       |
| 是否允许安排教师     | 为以后早读、晚自习值班预留     |
| 是否计入普通课时     | 是否计入教学任务的每周课时     |
| 是否显示在正式课程表 | 控制课程表展示                 |
| 是否显示在完整作息表 | 控制作息表展示                 |
| 是否启用             | 是否参与当前作息               |

---

### 4.10 教学任务

教学任务是排课系统中最重要的业务对象。

一条教学任务描述：

> 在某个学期，哪位教师给哪个班上哪门课，每周需要上多少节，以及默认在哪里上课。

示例：

```text
学期：2026—2027学年上学期
班级：七年级1班
课程：数学
教师：张老师
每周课时：5节
教室方式：使用本学期班级固定教室
```

另一个示例：

```text
学期：2026—2027学年上学期
班级：七年级1班
课程：体育
教师：王老师
每周课时：3节
教室方式：指定教室
指定教室：学校操场
```

建议字段：

| 字段       | 说明                         |
| ---------- | ---------------------------- |
| 教学任务ID | 系统唯一标识                 |
| 所属学期   | 对应学期ID                   |
| 班级ID     | 上课班级                     |
| 课程ID     | 上课课程                     |
| 教师ID     | 任课教师                     |
| 每周课时数 | 本任务一周需要安排几节       |
| 教室方式   | 本学期班级固定教室或指定教室 |
| 指定教室ID | 教室方式为指定教室时填写     |
| 状态       | 草稿、已确认、停用           |

基本规则：

- 第一阶段中，一条教学任务只对应一个班级、一位教师和一个课程。
- 教学任务必须明确所属学期。
- 教学任务中的班级必须属于该学期对应的学年。
- 同一学期、同一班级、同一课程只能有一条教学任务。
- 每周课时数必须是大于0的整数。
- 上下学期的任课教师和课时配置可以不同。
- 从上一学期复制的教学任务必须先作为草稿，由教务人员确认后再参与排课。
- 教师与课程的关联第一阶段只作为筛选和警告，不作为禁止保存教学任务的硬约束；停用教师不能用于新任务。
- 确认教学任务时，班级、所属年级、本学期配置、教师、课程和解析出的默认教室必须处于可用状态；教室无法解析的任务只能保留为草稿。
- 新建和复制任务均从草稿开始；草稿通过完整校验后才能确认，只有已确认任务参与排课和课时完整性统计。
- 已确认任务只有在没有排课结果时才能退回草稿或停用；已有排课结果时必须先显式移除课程。
- 停用任务不参与新排课和完整性统计；需要恢复时先回到草稿、重新检查后再确认，不能从停用直接跳到已确认。
- 已关闭学期中的任务状态不能修改；状态变化必须使用明确操作，不允许通用编辑接口任意写入状态值。

---

### 4.11 排课结果

排课结果表示一条教学任务被安排到了某个具体星期和课节。

例如：

```text
2026—2027上学期｜七年级1班｜数学｜张老师｜周一｜上午第1节｜教学楼201
```

建议字段：

| 字段       | 说明                                                             |
| ---------- | ---------------------------------------------------------------- |
| 排课结果ID | 系统唯一标识                                                     |
| 教学任务ID | 对应教学任务                                                     |
| 星期       | 使用 ISO 星期编号，1=周一、…、7=周日；默认启用1至5               |
| 课节ID     | 对应当前学期课节                                             |
| 实际教室ID | 本节课实际使用的教室                                             |
| 是否锁定   | 第一阶段允许教务人员保护已确认位置，避免普通移动、删除和批量迁移 |
| 排课来源   | 第一阶段固定为手工安排；未来增加自动排课时再扩展取值             |

排课结果通过教学任务确定所属学期。为便于查询，技术实现中也可以冗余保存学期ID，但必须与教学任务的学期保持一致。

实际教室的默认计算规则：

1. 如果教学任务指定了特殊教室，使用指定教室。
2. 如果教学任务没有指定特殊教室，使用该任务所属学期的班级固定教室。
3. 如以后允许临时换教室，可在排课结果中覆盖默认教室。

## 5. 学年与学期管理规则

### 5.1 新学年初始化

新学年不执行班级自动升年级，而是独立初始化。

建议流程：

```text
第一步：创建新学年
        ↓
第二步：创建上学期和下学期
        ↓
第三步：创建或导入本学年的年级班级
        ↓
第四步：设置上学期的班级固定教室和班主任
        ↓
第五步：设置上学期作息模板
        ↓
第六步：创建上学期教学任务草稿
        ↓
第七步：校验并开放学年和上学期，设置当前学期
        ↓
第八步：确认教学任务并进入排课
```

新学年中的班级可以：

- 完全手工创建；
- 从 UTF-8 CSV 导入；
- 参考上一学年班级清单生成草稿后再增删调整。

“参考上一学年创建”只是一种录入便利，不表示新旧班级存在继承关系，也不能自动复制学生或认定班级已经升年级。

这里的“草稿”只表示尚未提交的预览清单，不是持久化班级状态；用户确认后才创建新学年的独立班级记录，班级表不增加与学年/学期生命周期混淆的`draft`状态。

新学年可以自由调整：

- 年级中的班级数量；
- 班级名称和编号；
- 各学期的固定教室；
- 各学期的班主任；
- 任课教师；
- 每周课程课时。

---

### 5.2 上下学期切换

同一学年内，上下学期共用同一批班级身份。

从上学期进入下学期时，不执行升年级，也不重新创建班级。系统只创建下学期自己的：

- 学期班级配置；
- 作息模板；
- 教学任务；
- 排课结果。

系统可以提供“复制上一学期班级配置”和“复制上一学期教学任务”功能。班级配置复制后直接成为下学期独立配置；教学任务只复制来源学期中明确选中的已确认任务，来源草稿和停用任务不自动复制，复制结果必须为草稿。教务人员需要重新检查：

- 固定教室和班主任是否变化；
- 任课教师是否变化；
- 每周课时是否变化；
- 指定教室是否变化；
- 是否有新增或停开的课程。

第一阶段复制只允许从同一学年的较早学期复制到较晚学期。复制不得静默覆盖目标学期已有数据；若`学期+班级`配置、`班级+课程`任务或目标作息模板发生冲突，整批拒绝并返回冲突清单，由用户先处理后重试。

第一阶段默认同一学年内不重新分班。如果学校下学期重新分班，该场景暂不自动处理，可以停用原班级并手工创建新班级。

---

### 5.3 当前学年和当前学期

系统在业务上展示当前学年和当前学期，但只保存一个学校级“当前学期”指针；当前学年由该学期所属学年派生，不能分别保存两个可能不一致的来源。

系统展示：

```text
当前学年：2026—2027学年
当前学期：上学期
```

作用：

- 用户进入系统时默认展示当前学期数据；
- 新建教学任务时默认归入当前学期；
- 排课工作台默认加载当前学期；
- 课表查看默认展示当前学期。

注意：

- “当前学期”只是默认筛选条件。
- 首次初始化前，或关闭最后一个开放学期后，当前学期可以暂时为空，此时当前学年也为空；系统必须展示未设置状态，不能按系统日期自动猜测。
- 当前学期必须处于开放状态；已关闭学期不能设置为当前学期。
- 所有教学任务和排课结果仍必须保存明确的学期归属。
- 用户切换学期后，页面中的班级、教学任务和课表都必须随之切换。
- 用户在页面中查看其他学期只改变当前页面路由，不修改学校级当前学期。
- 禁止仅依赖系统当前时间推断数据归属。

---

### 5.4 历史数据保留

历史学年和历史学期的数据必须保留，不能因创建新学年、新学期或同名班级而被覆盖。

建议规则：

- 已结束学期默认只读。
- 历史班级、教师、课程和教室被引用后，不允许物理删除。
- 基础资料不再使用时采用“停用”，而不是删除。
- 历史学期的班级配置、作息模板、教学任务和排课结果保持只读。
- 历史教学任务和排课结果必须保持原学期归属。
- 排课结果必须保存当时实际使用的教室ID，因此以后修改其他学期的班级固定教室不会改写历史排课。
- 第一阶段不保存基础资料名称的历史文本快照。年级、教师、课程、班级或教室名称的受审计更正会同步反映在历史查询中，但其稳定ID、原学期归属和排课位置不得改变。
- 班级名称、年级等身份字段在该学年任一学期关闭后，普通用户不得修改；确需纠错时只能通过高权限、带审计的纠错操作完成。
- 如果以后需要“与当时导出文件逐字一致”的历史版本，应通过课表发布快照实现，不在第一阶段通过复制大量名称字段实现。

例如：

```text
2025—2026学年上学期｜七年级1班
2026—2027学年上学期｜七年级1班
```

虽然显示名称相同，但它们是两个不同学年的独立班级和独立课表。

---

### 5.5 生命周期状态

学年和学期统一使用以下生命周期状态：

```text
draft（草稿） -> open（开放） -> closed（关闭）
```

规则：

- `draft`允许准备班级配置、作息和教学任务草稿，但不能确认教学任务、放置课程、设为当前学期或作为正式历史学期。
- `open`允许有权限的用户确认教学任务并维护学期配置和课表。
- `closed`默认全部只读。
- “当前”不是生命周期状态，只由学校级当前学期指针表达。
- 学年只有在所属学期全部关闭后才能关闭。
- 关闭当前学期时必须在同一操作中切换到另一个开放学期，或在没有可选学期时清空当前指针；不能让当前指针继续指向已关闭学期。
- 学期只能在所属学年为`open`时进入`open`状态；重新打开已关闭学期时，如果所属学年已经关闭，必须先通过同一高权限操作重新打开学年，或拒绝本次操作。
- 学年和学期日期均按首尾包含处理；同一学年内各学期的日期范围不得重叠，前一学期`结束日期 <`后一学期`开始日期`，且学期日期必须落在学年范围内。学期间允许存在假期空档。
- 关闭学期前必须运行完整性校验；存在教学任务草稿或未排满任务时默认拒绝关闭，确需例外时必须由管理员填写原因并写入审计日志。资源冲突、跨学年关联等破坏数据可信度的硬错误不能通过强制关闭绕过。
- 重新打开已关闭学期是独立的高权限操作，必须记录操作者、原因和时间。
- 管理员只能物理删除从未开放且没有班级配置、作息、任务、课表或其他业务引用的误建草稿学期；误建学年还必须没有学期和班级。已有业务数据后只能按生命周期关闭，不能级联删除。
- 不再为学年或学期增加与生命周期含义重叠的“是否启用”字段。

---

## 6. 课节模型

### 6.1 课节分类

第一阶段将课节分为三类。

#### A. 普通课程课节

用于安排语文、数学、英语、体育等正式课程。

特征：

- 允许安排普通课程；
- 占用班级；
- 占用教师；
- 占用教室；
- 计入教学任务每周课时；
- 默认显示在正式课程表中。

示例：上午第1节、下午第2节。

#### B. 固定非课程课节

用于表示学校固定作息，但第一阶段不安排具体课程和教师。

特征：

- 不允许安排普通课程；
- 不计入普通课程课时；
- 默认显示在完整作息表中；
- 可以不显示在正式课程表中。

示例：早操、课间操、课间活动、午休。

#### C. 自习管理课节

用于表示早读、晚自习等可能存在但不属于普通课程的课节。

特征：

- 默认不允许安排普通课程；
- 默认不计入普通课程课时；
- 可以选择是否在学校中启用；
- 可以选择是否显示在正式课程表中；
- 为以后安排辅导教师或值班教师预留能力。

示例：早读、晚自习1、晚自习2。

第一阶段只负责展示这类课节，不负责安排早读和晚自习教师。

#### 课节字段一致性

第一阶段不允许用户任意组合“课节类型、允许排课、计入课时”三个字段。系统必须按类型保存以下规范值：

| 课节类型   | 允许排普通课程 | 计入普通课时 | 允许安排教师               | 正式课程表         | 完整作息表 |
| ---------- | -------------- | ------------ | -------------------------- | ------------------ | ---------- |
| 普通课程   | 是             | 是           | 是                         | 必须显示           | 必须显示   |
| 固定非课程 | 否             | 否           | 否                         | 可配置，默认不显示 | 必须显示   |
| 自习管理   | 否             | 否           | 可配置，为后续值班功能预留 | 可配置             | 必须显示   |

所有已启用课节都必须显示在完整作息表；已停用课节不能参与新排课。系统不得允许隐藏一个仍可排课的普通课程课节，否则正式课程会在课程表中消失。

### 6.3 正式课程表与完整作息表

系统需要区分两种展示方式。

#### 正式课程表

主要用于教师、学生和教务人员查看正式课程。

默认显示：

- 允许排普通课程的课节；
- 已经排入的正式课程。

默认不显示：

- 早操；
- 课间操；
- 课间活动；
- 午休；
- 晚自习。

早读是否显示可以由学校配置。

#### 完整作息表

用于查看学校一天的完整时间结构。

可以显示：

- 早操；
- 早读；
- 普通课程；
- 课间操；
- 课间活动；
- 午休；
- 晚自习；
- 其他学校自定义课节。

这种设计可以避免把晚自习强制纳入正式课程表，同时保留不同学校的配置能力。

可以用两条链路理解：

```text

├── 班级
└── 学期
    ├── 学期班级配置
    ├── 作息模板
    ├── 教学任务

```

```text
教学任务 = 学期 + 班级 + 课程 + 教师 + 每周课时 + 教室规则
排课结果 = 教学任务 + 星期 + 课节 + 实际教室
```

### 7.1 关键数据一致性规则

- 班级所属学年必须与教学任务所属学期的学年一致。
- 学期班级配置中的班级必须属于该学期的学年。
- 排课结果只能使用其所属学期的作息模板和课节。
- 排课结果所属学期必须与教学任务所属学期一致。
- 排课结果中的班级、教师、课程必须与教学任务一致。
- 排课结果中的星期必须在作息模板中启用，课节必须启用且允许排普通课程。
- 不同学期的数据相互隔离，不参与彼此的冲突判断。
- 不同学年的同名班级是独立记录。
- 新学年数据不能修改或覆盖历史学年数据。

---

## 8. 第一阶段排课规则

第一阶段先处理必须满足的硬约束。

所有冲突判断都限定在同一个学期内。

### 8.1 班级不能冲突

同一个学期、同一个班、同一个星期、同一个课节，只能有一条正式课程记录。

错误示例：

```text
2026—2027上学期｜七年级1班｜周一上午第1节｜数学
2026—2027上学期｜七年级1班｜周一上午第1节｜英语
```

这两条记录不能同时存在。

---

### 8.2 教师不能冲突

同一个学期、同一位教师、同一个星期、同一个课节，只能承担一个教学任务。

错误示例：

```text
2026—2027上学期｜张老师｜周二上午第2节｜七年级1班数学
2026—2027上学期｜张老师｜周二上午第2节｜七年级2班数学
```

不同学期中的相同星期和课节不构成冲突。

---

### 8.3 教室不能冲突

同一个学期、同一个教室、同一个星期、同一个课节，只能被一条课程占用。

例如，学校只有一个计算机教室，则同一学期同一课节不能同时安排两个班上信息技术课。

普通班级固定教室也参与教室冲突判断，但由于每个班通常固定使用自己的教室，正常情况下不会冲突。

---

### 8.4 只能在允许排课的课节安排普通课程

普通课程只能安排在“是否允许排普通课程”为“是”的课节中。

以下课节默认不能排普通课程：

- 早操；
- 课间操；
- 课间活动；
- 午休；
- 晚自习。

---

### 8.5 每周课时必须满足

每条已确认教学任务设置了多少节课，当前学期的排课结果中就必须存在多少条有效课程记录；停用任务不参与完整性统计，草稿任务会使学期默认不能关闭。

例如：

```text
2026—2027上学期｜七年级1班数学｜每周5节
```

排课完成后必须正好存在5条对应记录。

系统需要显示：

- 应排课时；
- 已排课时；
- 未排课时；
- 是否已经完成。

教学任务确认前还必须执行基础容量检查。设“每周可排槽位数 = 启用星期数 × 已启用普通课程课节数”，则单条任务课时，以及同一班级、同一教师的已确认任务课时合计，都不能超过该槽位数。教室容量按“该教室已有排课课时 + 尚未排课且按当前规则将使用该教室的剩余课时”计算，也不能超过槽位数。该检查只能发现显然不可能完成的配置，不代表已经证明整张课表一定可排。

任务草稿可以暂时不满足容量要求；确认任务，或修改星期、课节、固定教室等配置后导致已确认任务超过容量时，操作必须被拒绝并返回具体超限资源。

---

### 8.6 教室默认规则

- 普通课程默认使用教学任务所属学期的班级固定教室。
- 体育、音乐、实验、信息技术等课程可以在教学任务中指定特殊教室。
- 排课结果仍保存实际教室，便于冲突检查和以后临时换教室。

---

### 8.7 时间重叠校验

第一阶段主要按照“学期 + 星期 + 课节ID”判断课程冲突。

同时，保存课节时也应检查开始时间和结束时间，避免同一作息模板中的两个课节发生异常重叠。

时间区间按左闭右开`[开始时间, 结束时间)`判断，因此上一课节结束时间等于下一课节开始时间是允许的；只有`A开始 < B结束`且`B开始 < A结束`时才算重叠。

例如：

```text
上午第1节：08:00—08:45
上午第2节：08:40—09:25
```

这两个课节重叠，系统应提示配置错误。

---

### 8.8 学年学期归属校验

系统必须阻止以下错误：

- 将2026—2027学年的班级加入2027—2028学期的教学任务；
- 将上学期教学任务排入下学期课节；
- 在当前学期编辑时误覆盖历史学期排课结果；
- 因班级同名而错误关联到其他学年的班级。

---

### 8.9 启用状态与可排条件

一条课程只有同时满足以下条件才能新增或移动：

- 学期处于`open`状态；
- 星期在该学期作息模板中启用；
- 课节处于启用状态且允许排普通课程；
- 教学任务处于已确认状态；
- 班级、所属年级和本学期班级配置处于正常状态；
- 教师、课程和最终解析出的教室允许参与新排课。

基础资料后来被停用时，已有历史记录继续显示。对开放学期中已有教学任务的处理必须显式提示，不得静默删除或改写课表。

---

### 8.10 已有课表后的修改规则

- 教学任务已有排课结果后，不允许普通编辑学期、班级、课程或教师。
- 每周课时可以增加；减少时不得低于当前已排课时数。
- 教学任务已有排课结果后，普通编辑不能直接修改教室方式或指定教室。需要变更时必须使用独立的“迁移已有课程教室”操作，在同一事务中重新检查全部教室冲突。
- 教学任务只有在没有排课结果时才能物理删除；否则只能先移除当前学期排课结果，再停用任务。关闭学期中的任务不得修改。
- 已被课表引用的星期不能停用，已被引用的课节不能删除、停用、隐藏或改成不可排课。
- 修改开放学期的课节名称、开始时间、结束时间或顺序时，必须重新执行重叠校验并使课表修订号失效。
- 修改本学期班级固定教室只影响之后新放置的课程，已有排课结果继续保存原实际教室；若需批量迁移，必须使用独立、带冲突校验和审计的操作。
- 已锁定排课结果不能被普通移动、删除或批量迁移；用户必须先通过显式操作解锁，锁定不能绕过学期关闭和权限规则。

---

## 9. 第一阶段功能模块

第一阶段建议包含以下模块。

### 9.1 身份与权限

用于：

- 账号密码登录和退出；
- 管理员、排课员、只读查看者三类角色授权；
- 停用账号和由管理员重置密码；
- 使用临时密码创建或重置的账号必须在下次登录后先修改密码，完成前不得访问其他业务功能；
- 账号停用、角色变更或管理员重置密码后，已有登录会话必须立即失效；
- 通过部署命令安全创建首个管理员，不在仓库中提交默认密码。

第一阶段不提供公开注册、邮件找回密码、单点登录和教师个人账号。

管理员拥有排课员和只读查看者的全部权限；排课员不能管理用户，也不能执行重新打开历史学期、强制关闭或历史纠错等管理员操作。

系统必须始终保留至少一个启用的管理员账号；停用或降级最后一个启用管理员的操作必须被拒绝。

---

### 9.2 学年学期管理

用于：

- 创建和编辑学年；
- 创建上学期和下学期；
- 设置学校级当前学期，并展示由其派生的当前学年；
- 切换查看历史学年、历史学期；
- 将已结束学期设置为只读；
- 初始化新学年。

第一阶段不提供自动升年级功能。

---

### 9.3 基础资料管理

用于管理：

- 年级；
- 教师；
- 课程；
- 教室。

基础资料被历史数据引用后，只允许停用，不允许直接删除。

多个用户同时维护基础资料时，基于旧页面的提交不得静默覆盖其他人已经完成的修改；系统必须拒绝过期提交，提示用户刷新后重新确认。

---

### 9.4 学年班级管理

用于管理选定学年中的班级：

- 新增班级；
- 通过 UTF-8 CSV 预检并批量导入班级；
- 设置所属年级；
- 设置班级名称和编号；
- 停用班级；
- 可选：参考上一学年班级清单生成草稿。

该模块不处理学生分班和班级升年级关系。

CSV 导入至少固定表头、编码、空值规则、同学年重复判断和逐行错误格式。第一阶段导入只新增班级，不批量覆盖已有班级；与已有班级名称或编号冲突的行必须报错，已有班级应通过单条编辑流程修改。提交必须在事务中执行，预检令牌必须防止重复提交；成功响应丢失后重复提交时，系统应能返回第一次提交的结果摘要，不允许产生重复数据或无法识别的半成功状态。预检后相关基础资料或班级数据发生变化时，旧预检结果必须失效并要求重新预检。

---

### 9.5 学期班级配置

用于管理选定学期中各班的：

- 固定教室；
- 班主任；
- 启用状态；
- 从同一学年的上一学期复制配置。

该模块必须校验班级与学期属于同一学年，并遵守已关闭学期只读规则。

---

### 9.6 作息设置

用于设置当前学期学校一天的全部课节。

需要支持：

- 新增、编辑、删除未被使用的课节；
- 设置课节名称；
- 设置开始和结束时间；
- 调整显示顺序；
- 设置课节类型；
- 由课节类型自动确定是否允许排普通课程和是否计入课时，不提供相互矛盾的独立开关；
- 设置是否显示在正式课程表；
- 启用或关闭晚自习等可选课节；
- 从上一学期复制作息模板后独立修改。

修改新学期作息不能影响历史学期。

---

### 9.7 教学任务管理

用于录入当前学期每个班需要完成的课程任务。

每条任务至少设置：

- 学期；
- 班级；
- 课程；
- 教师；
- 每周课时；
- 教室方式；
- 指定教室（教室方式为“指定教室”时必填）。

系统应支持：

- 按年级、班级、教师和课程筛选；
- 从上一学期复制教学任务为草稿；
- 批量确认草稿；
- 校验班级与学期是否属于同一学年。

---

### 9.8 排课工作台

排课工作台用于产生和调整选定学期的周课表。

第一阶段至少支持：

- 明确显示当前正在编辑的学年和学期；
- 按班级查看周课表；
- 将教学任务安排到某个可排课课节；
- 删除或移动已排课程；
- 显式锁定或解锁已排课程；
- 显示每条教学任务剩余未排课时；
- 保存排课结果；
- 对冲突操作进行即时提示；
- 防止误编辑其他学期数据。

第一阶段只提供手工放置、移动和删除。自动排课及候选方案预览属于后续版本；增加自动排课时可以复用教学任务和正式排课结果，但仍需新增求解任务与候选结果数据结构。

学年班级、学期班级配置、作息、教学任务和课表同样适用并发保护：用户基于旧页面提交时，系统必须拒绝并提示刷新，不能用旧数据覆盖已经提交的新状态。

---

### 9.9 课表查看与历史查询

第一阶段至少提供三种视图：

1. 班级课表；
2. 教师课表；
3. 教室课表。

另外提供两种显示模式：

- 正式课程表；
- 完整作息表。

所有课表视图必须带有明确的学年和学期筛选条件。

历史学期默认只读，允许查看和导出，但不能被当前学期操作覆盖。第一阶段导出格式为 UTF-8 CSV，至少支持按班级、教师和教室导出当前筛选结果，并防止 CSV 公式注入。

---

## 10. 基本业务流程

### 10.1 新学年初始化流程

```text
创建新学年
    ↓
创建上学期和下学期
    ↓
创建或导入本学年班级
    ↓
设置上学期班级配置（固定教室和班主任）
    ↓
设置上学期作息模板
    ↓
创建上学期教学任务草稿
    ↓
校验并开放学年，再开放上学期并设置为当前学期
    ↓
确认教学任务
    ↓
进入排课
```

该流程不包含学生升年级和班级继承处理。

---

### 10.2 新学期开始流程

```text
选择待启用的新学期（只切换页面，不修改学校当前学期）
    ↓
复制或新建本学期班级配置
    ↓
复制或新建作息模板
    ↓
复制上一学期教学任务为草稿，或重新录入
    ↓
检查并调整教师、课时和教室
    ↓
校验并开放新学期，设置为当前学期
    ↓
确认教学任务
    ↓
重新排课
```

上学期课表不会被覆盖。

---

### 10.3 正常排课流程

```text
选择学年和学期
        ↓
确认学期处于开放状态
        ↓
确认当前学期班级配置、教师、课程和教室
        ↓
确认当前学期作息模板和课节
        ↓
录入或确认每个班的教学任务
        ↓
将教学任务安排到每周可排课课节
        ↓
系统检查班级、教师和教室冲突
        ↓
检查所有教学任务是否达到每周课时数
        ↓
查看班级、教师和教室课表
```

---

### 10.4 历史课表查看流程

```text
选择历史学年
    ↓
选择历史学期
    ↓
查看班级、教师或教室课表
    ↓
只读展示或导出
```

---

学期：2027—2028学年上学期

## 12. 第一阶段验收标准

系统满足以下条件时，可以认为第一阶段基础模型成立：

### 12.1 身份与权限

- 能通过账号密码登录和退出。
- 管理员、排课员和只读查看者由后端强制执行不同权限。
- 临时密码账号在完成首次改密前不能访问其他业务功能。
- 停用账号不能继续登录，账号停用、角色变更或密码重置会使已有会话失效。
- 不能停用或降级最后一个启用管理员。
- 仓库和初始化数据中不存在通用默认密码。

### 12.2 学年学期

- 能创建学年。
- 能在学年下创建上学期和下学期。
- 学年开放前必须恰好具有顺序1、2两个学期，不能创建第三学期。
- 能设置唯一的学校级当前学期，并正确派生当前学年。
- 生命周期状态与当前学期指针不会出现相互矛盾的数据。
- 只有完全空的误建草稿学年或学期可以由管理员物理删除，删除不会级联清除业务历史。
- 学期日期位于所属学年内且互不重叠，关闭学年后不能单独留下开放学期。
- 作息模板不完整时学期不能转为开放状态。
- 能切换查看历史学年和历史学期。
- 历史学期数据不会被新学期数据覆盖。

### 12.3 班级

- 班级必须属于具体学年和年级。
- 不同学年可以存在同名班级。
- 同一学年内班级名称不能重复。
- 上下学期共用本学年的班级身份，但分别保存学期班级配置。
- 新学年能够重新创建或通过 UTF-8 CSV 预检、导入新班级；导入不会覆盖已有班级，重复提交不会重复创建数据且能识别原提交结果，预检后的相关数据发生变化时旧令牌不能继续提交。
- 同一班级可以在上下学期配置不同固定教室和班主任。
- 系统不要求建立新旧学年班级继承关系。

### 12.4 基础排课

- 能建立教师、课程和教室。
- 每个班能够在具体学期配置固定教室。
- 能设置包含早操、早读、课程、课间操、课间活动、午休和晚自习的完整作息。
- 一个开放学期恰好有一套全校共用作息，所有启用星期共用同一组课节。
- 能明确区分可排普通课程和不可排普通课程的课节。
- 能为具体学期的班级创建教学任务。
- 教学任务只能按草稿、已确认、停用的明确状态规则迁移，已有排课结果的任务不能直接退回草稿或停用。
- 班级创建学期教学任务前必须已有该学期的班级配置。
- 教学任务中的班级必须与学期属于同一学年。
- 能把教学任务安排到周一至周五的可用课节。
- 不能在停用星期、停用课节、不可排课课节或未确认任务上创建课程。
- 能阻止同一学期同一班级在同一时间上两门课。
- 能阻止同一学期同一教师在同一时间给两个班上课。
- 能阻止同一学期同一教室在同一时间被重复占用。
- 已锁定课程在解锁前不能被移动、删除或批量迁移。
- 能统计每条教学任务应排、已排和未排课时。
- 能在确认教学任务和修改作息时阻止班级、教师或教室总需求超过每周可排槽位数。
- 两个用户同时修改基础资料或同一学期数据时，过期提交会收到明确冲突提示，不会静默覆盖较新的修改。
- 第一阶段不提供自动排课入口。

### 12.5 查看与历史

- 能分别查看班级、教师和教室课表。
- 所有课表都明确显示所属学年和学期。
- 正式课程表默认不显示晚自习等非正式课程课节。
- 完整作息表可以显示学校启用的所有课节。
- 已结束学期默认只读。
- 停用教师、课程、教室和班级不会破坏历史课表。
- 修改其他学期的班级固定教室不会改变历史排课实际教室。
- 能按班级、教师和教室导出 UTF-8 CSV，并防止公式注入。

## 14. 当前设计结论

第一阶段系统围绕以下十二个核心对象建立：

1. 学年；
2. 学期；
3. 年级；
4. 班级；
5. 学期班级配置；
6. 课程；
7. 教师；
8. 教室；
9. 作息模板；
10. 课节；
11. 教学任务；
12. 排课结果。

核心设计原则如下：

> 班级属于学年；教学任务和排课结果属于学期。

> 新学年重新创建或导入班级，不执行自动升年级，也不追踪学生进入了哪个新班。

> 同一学年内，上下学期共用班级身份，但固定教室、班主任、任课教师、每周课时、作息模板和排课结果按学期分别配置。

> 当前学期只是学校级默认操作范围，当前学年从当前学期派生；所有数据仍必须保存明确的学期归属，历史学期数据不能被覆盖。

> 课节不等于普通课程节次。早操、早读、课间操、午休和晚自习都可以作为课节存在，但只有被标记为“允许排普通课程”的课节才能参与正式课程排课。

> 晚自习是学校可选的自习管理课节，不应被系统强制作为正式课程，也不应默认显示在正式课程表中。

> 第一阶段只做手工排课和硬约束校验；自动排课、候选方案、课表发布和版本审批属于后续版本。
